# 技术分享视频验收

围绕 `brief.md` 的分享目标检查成片。技术文件检查和讲解效果检查分别记录；自动校验无法证明观众理解，AI 自检也不能代替团队反馈。

在共用检查之外，按 [视频风格](styles.md) 读取所选指南的检查项，在 `output/review.md` 记录实际采用的风格与检查结果。风格符合预期不能代替内容正确性和音画同步检查。

## 检查内容与讲解

| 检查项 | 通过条件 | 问题如何定位 |
| --- | --- | --- |
| 作者意图 | 重要观点、经验范围和必须保留的内容得到表达，省略有理由 | 对照 brief 与 outline，列出缺失章节或变义口播 |
| 技术含义 | 前提、状态变化、代码行为、单位与边界准确，示意和实测区分清楚 | 核对原文与演示的初始状态、变化和结果 |
| 理解顺序 | 新概念有足够铺垫，步骤之间有因果或逻辑连接 | 按首次接触主题的同事视角逐章检查 |
| 画面作用 | 关键机制能从画面看出，画面与口播没有矛盾 | 指出哪个场景只是复述文字、缺少关键变化 |
| 会议观看 | 代码、标签和字幕在缩小预览后仍可读，重点明确，停留时间足够 | 检查最长代码、最密图示、最长字幕及关键状态 |
| 音画表达 | 术语发音可理解，句尾完整，讲到的对象及时突出，字幕与实际口播一致 | 播放关键演示与转场，记录问题时间点 |

每章完成后检查该章。最终检查整片的章节衔接与节奏，条件允许时完整播放试听；只有截图能力时检查画面并明确无法判断动态同步或声音。静态图不能证明动画完整，存在音频轨不能证明配音自然。

将每个预期收获转成具体问题，依据实际成片写出答案并核对，例如“为什么缓存命中后不访问源数据？”和“源数据更新后有什么风险？”。若答案需要视频没有给出的知识，补充相应讲解或调整目标。这里验证的是视频是否提供了答案，不声称团队已经掌握。

## 检查连续讲解与动作节奏

在精修前检查代表片段的粗排，成片后再复查。用三种互补方式定位问题：

- 暂时忽略声音：能否追踪对象、变化方向和结果；画面是否只是在显示标题或正文。这个检查不要求无声也能学会全部内容。
- 对照口播播放：提到的对象是否在场，因果动作是否按顺序发生；主焦点是否被同时出现的其他动效打断。
- 暂停在关键变化前后：身份、标签、连线与状态是否准确，结论是否有可观察的依据。

记录需要修复的具体症状，如“标签先动而连接未更新”“术语出现但对象尚未建立”“镜头移开时仍需读代码”“结论一出现就切走”。机械进场、无意义停滞和动作拥挤都要回到分镜处理，不用给每幕添加更多特效来掩盖。

片段复杂度不同，不用统一的镜头秒数、动作数量或主观总分代替判断。确有内容缺失、技术误导、遮挡或句尾截断时先修复；只有视觉偏好差异时如实记录，留待用户反馈。

## 开场、动作与技术文字专项检查

- 独立检查第 0 帧是否能完整表达主题，再检查开场几秒的连续过程；缺标题、孤立符号或半成品关系图均需修复，不能仅记录“已抽查”。
- 对旋转、变形和移动连线检查完整动作，覆盖起点、途中多个状态和终点，核对中心、箭头连接、遮挡和状态顺序。缺少连续播放能力时采用连续密集抽帧，并明确这不能替代完整播放听审。
- 核对常驻文字的用途；制作标记不进入成片，章节导航避免与场景标题重复。
- 对照讲稿、命令和显示字幕检查参数符号、大小写、数字、版本、单位；配音读法不同于技术写法时，验证明确映射，不要求显示字幕复制发音文本。

选用内置组件后，检查示例姓名、命令、图表数值和占位文字是否已替换，主题下的对比度是否足够，模板是否遮挡标题或字幕。代码与流程场景还要检查主体变化：若只剩文字入场、打字和整页转场，回到分镜补足机制演示。组件通过测试不能代替当前内容的检查。

## 检查文件与时间线

运行分镜 `--ready` 校验和 TypeScript 检查，按实际 composition 核对总帧数、音频起点及素材。导出后检查文件可读取、视频轨、分辨率、帧率和时长；配音模式检查音轨，并在工具可用时解码检查。抽查首尾、复杂场景、最长文字及章节切换；发现问题后扩大到相关范围。

旁白变化后重新测量对应音频，更新分镜、composition、字幕和章节时间索引。只有颜色等不改变排期的修改无需重做配音。保留已有输出，用新的文件名渲染修改版。

## 记录、修复与交付

在 `output/review.md` 记录：检查的文件或版本、各项通过／待修复／未检查的状态、证据所在场景或时间点、发现的问题、修复及复查结果。无法听审或播放时注明原因，不填“通过”。能修复的问题先修复；核心技术含义仍有疑问时说明阻塞，不将其作为已验收成片交付。

完整制作同时按 [harness.md](harness.md) 写入 `output/review.json`，绑定当前 MP4 的 SHA-256 并列出证据路径，再 checkpoint `review`。记录存在只说明审查者作出了结论，程序不会自动证明结论正确；未检查项必须保留，视频变化后重新审查。

使用 [chapters.mjs](../scripts/chapters.mjs) 从最终分镜生成章节标题、真实起止时间和学习目标，将标准输出保存到项目 `output/chapters.md`：

```text
node "<Skill目录>/scripts/chapters.mjs" "<项目目录>/storyboard.json"
```

索引用于会议暂停、定位和讨论，使用各幕实际帧数顺序累加，不读取 outline 的估时。每次改动排期后重新生成；review 阶段会拒绝缺失或过期索引。不要手改生成表格，额外讨论提示记录到 `output/review.md`。当前 harness 只验收顺序排期的全片，重叠转场需先调整时间线协议，不能套用此索引。

交付 MP4、实际时长、章节索引、检查结果和可编辑工程。质量改进依据具体反馈，例如“第三章仍看不懂请求去向”，返回对应场景修改；不要用缺少证据的分数代替验收。
