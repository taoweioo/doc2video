# 分镜约定

`storyboard.json` 是本 Skill 的制作中间文件，不是 Remotion 原生格式。Agent 根据它生成 composition；Remotion 不会自动读取并理解这些字段。

完整草稿示例见 [storyboard.example.json](../assets/storyboard.example.json)，对应原文见 [example.md](../assets/example.md)。

## 从章节计划到分镜

读取 `brief.md`、`outline.md` 和原文后再写分镜。章节 ID 与 outline 一致，每幕的 `purpose` 回答“团队看完这一幕应理解什么”。按需要把一个讲解步骤拆成多幕，同一章连续播放；不要按字数机械切片。

口播说明原因、判断和边界，画面展示对象、关系和变化。解释命令时直接说明行为和选项用途，例如“`-d` 表示后台运行”，不为解释操作额外引入“短参数”等未铺垫的分类术语。避免照读屏幕、逐行朗读代码或重复解释受众已知的术语。保留作者的技术判断，不为制造吸引力添加未经证实的结论。条件、反例和代价与结论一起编排。

`visual` 说明初始状态、关键变化、最终状态和与口播的同步点。按内容选择演示方式：

| 内容 | 画面应帮助观众看清什么 |
| --- | --- |
| 执行流程 | 输入经过哪些步骤，控制或数据流向哪里，何时产生输出 |
| 代码行为 | 当前执行位置、相关变量或状态的变化、结果与原因 |
| 架构关系 | 组件职责、调用方向、边界及关键路径 |
| 方案比较 | 在相同条件下，各方案的行为差别、收益与代价 |
| 故障复盘 | 正常路径如何偏离，证据如何支持原因判断 |

例如说明缓存风险：先保留缓存与数据源相同的状态，让数据源发生更新而缓存保持旧状态，再展示请求读到旧值。标注为示意，不伪装成原文未提供的运行截图或实验。

一幕可以使用多种表现方式，但它们都应服务 `purpose`。强调当前讲到的对象，给代码阅读和状态对比留时间。全片的术语、对象标识保持一致。按 [视频风格](styles.md) 读取所选指南，将其用于具体演示设计；风格不能替代本幕的讲解目的，也不要求每幕都有装饰动画。

## 将一幕写成可执行的讲解过程

一幕是一个完整的讲解单元，可以包含多个动作和景别，不等同于一页画面或一句口播。继续使用 `visual` 字符串，按实际需要写明以下内容，无需另建一份分镜表或新增必填字段：

| 内容 | 分镜需要说清什么 |
| --- | --- |
| 承接与初始状态 | 哪些对象从上幕留下，当前值与连接是什么；新对象为何出现 |
| 注意力焦点 | 当前希望观众看哪里；标签靠近哪个对象；哪些背景信息可以减弱 |
| 触发与动作 | 对应哪段口播，由哪个事件引起什么变化；记录 [动效配方](motion.md) 和所选 [内置组件](motion-library.md) 的 ID、作用对象与触发点；没有匹配组件时说明需要定制的演示 |
| 结果与停留 | 动作后观众应看到什么差别；哪些内容保持不变；何时留时间阅读或比较 |
| 镜头与衔接 | 是否需要靠近、拉远或分屏；下一幕继承什么；切换是否影响理解 |
| 素材与证据 | 使用原文中的什么代码、数据或图示；新增图形哪些是教学示意 |

草稿以口播中的短语作为动作触发线索，不虚构精确时间。获得音频后再将线索对应到实际边界和帧数。一个短语可能包含多个动作，先后顺序由含义决定，不把所有动作堆在句首。

编排时建立“看见对象 → 观察变化 → 理解结果”的注意力顺序。出现新名词时先提供识别它的视觉线索，再讨论关系。主要变化结束后保留结果，随后交接焦点；不要在观众还需阅读代码时同时移动镜头和切换字幕之外的大段文字。

## 画面与口播共同解释

口播解释原因、条件和判断；画面提供可观察的过程、关系或证据。画面正文只放必要的名称、条件和结论，避免同时出现图解、整段正文和重复的全文字幕。字幕是独立的阅读辅助，仍按配音规范保留，不因减少正文重复而删除。

在一幕中保持对象的身份和位置可追踪。改变标签引用时保留被引用对象；创建新实例时让它作为新对象出现；重启原实例时保留身份。抽象形状之间的平滑变化不能暗示错误的技术关系。原文有真实代码或结果时，优先展示相关部分；机制示意不冒充运行证据。

避免只写“展示架构图，然后高亮缓存”。可写为：“沿用上一幕的请求与数据源；先靠近请求的往返路径。讲到保存结果时，在路径中加入缓存并写入同一示意值；讲到后续命中时，让请求在缓存处折返，数据源保持不动。最后拉远比较长短路径，保留结果，再承接下一幕的数据更新。”

不要求每幕必须发生镜头移动。按机制、代码阅读、状态比较交替安排表达方式；需要运动时说明目的，需要停留时说明观众要读什么。设计依据见 [design-sources.md](design-sources.md)。

## 字段

| 字段 | 约定 |
| --- | --- |
| `version` | 新分镜为数字 `2`；校验器继续接受旧版 `1` |
| `title`、`language`、`audience` | 非空文本 |
| `style` | 新任务记录所选风格 ID，默认 `technical-motion`；版本 2 的结构校验仍允许省略，旧的自由文本说明继续有效。选择规则见 [styles.md](styles.md) |
| `chapters` | 版本 2 必填，按播放顺序排列的非空数组；每项含唯一 `id`、非空 `title` 和学习目标 `objective` |
| `width`、`height`、`fps` | 正整数；默认 1920、1080、30 |
| `narrationMode` | `tts`、`provided` 或 `none` |
| `scenes` | 按播放顺序排列的非空数组 |
| `scenes[].id` | 唯一 ID，仅使用小写字母、数字和连字符 |
| `chapterId` | 版本 2 必填，引用 `chapters` 的 ID；场景按章节顺序连续排列，每章至少一幕 |
| `purpose` | 版本 2 必填的非空文本，本幕要让观众理解的内容 |
| `sourceQuotes` | 原文直接摘录的非空字符串数组，支撑本幕观点 |
| `narration` | 完整口播；无声模式可为空字符串 |
| `speechReplacements` | 仅 TTS 可用的可选数组；每项为 `{ "text": "8080", "spoken": "八零八零" }`，只处理明确指定的术语；无需求时省略 |
| `onScreen` | 画面显示的短文字，至少一项 |
| `visual` | 具体画面结构、动作及与口播同步的说明 |
| `estimatedSeconds` | 草稿估时，大于 0 |
| `durationInFrames` | 实际制作阶段的总帧数，正整数 |
| `leadFrames`、`tailFrames` | 配音前后留白，非负整数；制作阶段必填 |
| `audio.src` | 配音模式制作阶段必填，相对生成工程 `public/` 的本地音频路径 |
| `audio.durationSeconds` | 实际测量的音频时长，大于 0 |

`sourceQuotes` 保留原文字符；校验时仅合并空白。引用检查只能证明原句存在，不能证明改写结论正确，仍需语义审查。概括多个观点时列出对应的多处引用。

章节 ID 使用与场景 ID 相同的格式。旧版 `1` 保留原约定，包括必填的 `style`；不会自动改写旧文件。新任务使用版本 2。`objective`、`purpose` 的文本存在不代表目标明确，需按分享目标作语义检查。

标准讲稿只编辑 `scenes[].narration`，保留命令、选项、端口、版本与单位的正确拼写。配音需要特殊读法时使用可选的 `speechReplacements`，按 [audio.md](audio.md) 派生配音输入与显示字幕，不把发音写法当成最终字幕。修改讲解顺序时同步 outline 和章节字段；口播修改后重新核对引用与演示，按 [audio.md](audio.md) 更新配音。术语的 TTS 发音处理不改变代码、API 名称或字幕中的技术拼写。

## 从估时切换到音频排期

有配音时必须满足：

```text
durationInFrames >= leadFrames + ceil(audio.durationSeconds × fps) + tailFrames
```

每幕的起始帧为此前各幕 `durationInFrames` 的累加。第一版默认顺序拼接，转场动画放在场景内部，避免转场重叠导致总时长和音频错位。若主动采用重叠转场，需要单独核算时间线并记录，不能继续套用顺序累加结果。

制作完成后，composition 必须使用这些实际帧数。音频在本幕的 `leadFrames` 开始；校验通过不能代替代码与 JSON 的一致性检查。

无声模式也填写实际帧数和留白，按观众阅读时间安排；不设置 `audio`。画面文字与字幕区分：`onScreen` 是摘要，字幕来自实际口播或录音转写。

## 校验方式

将路径占位符替换为当前系统中的实际路径，保留引号以支持带空格的目录。

```text
node "<本Skill目录>/scripts/validate-storyboard.mjs" "<任务目录>/storyboard.json" --source "<任务目录>/source.md"
node "<本Skill目录>/scripts/validate-storyboard.mjs" "<任务目录>/storyboard.json" --source "<任务目录>/source.md" --ready --public-dir "<任务目录>/public"
```

退出码 `0` 表示通过，`1` 表示输入、结构、来源或文件检查失败。`--ready` 要求所有制作字段完整，并检查音频文件存在、非空且未越出 `public/`。它不解码音频、不自动测量时长，也不判断画面质量。
